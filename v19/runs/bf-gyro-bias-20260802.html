A gyro fault the firmware had to fly through.

A phantom +2000 LSB bias is forced onto the gyro X axis while unmodified Betaflight is holding a hover. Nothing tells the firmware. It reads the rotation as real and drives its motor mix against it, which is the whole point: the fault reaches the control loop the way a broken sensor would.

What this is, exactly

Read this before you weigh the run

Every number and every trace above comes from one captured run on the bench. The traces are drawn from the 1883 stored samples per channel, not illustrated.

It does not yet reproduce. Three back to back runs of this scenario gave PASS, FAIL, PASS. The known cause is on our side, not the firmware's: after a scenario that tumbles the model, Betaflight's attitude estimate can stay tilted while the plant is level, so the next run either refuses to arm or fights a phantom lean. Until that is closed we would not put this forward as proof of anything.

This ran on Oracova development hardware. Augur One, the board on the product page, is in fabrication.

The rest of the suite

Same harness, twelve scenarios, five consecutive runs. These four passed every time:

failsafe_rc_loss fails by construction here, and it is worth saying why: the scenario stops sending RC to simulate a lost link, but on this gateware the fabric keeps re-emitting the last frame, so the firmware never sees a loss. The test is invalid on this signal path, not failing.
